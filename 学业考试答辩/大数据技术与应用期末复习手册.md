## 三、Part 1 · HDFS 分布式文件系统

### 🧱 3.1 零基础入门：HDFS 是什么？

**一句话理解**：HDFS 就是 Hadoop 生态里的**硬盘**——它把超大文件切成小块，存到一群便宜电脑上，还自动备份，不怕某台电脑坏了。

#### 核心架构（考试必考问答题）

```
┌─────────────────────────────────────────────────────┐
│                   Client（客户端）                     │
│              告诉 NameNode "我要读/写"                  │
└──────────────┬──────────────────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────────────────┐
│  NameNode（主节点，只有 1 个）                          │
│  • 保存文件系统的【目录树】和【块位置映射表】              │
│  • 不存真正的数据，只存元数据（metadata）                 │
│  • 启动时消耗内存大                                    │
│  • Hadoop 2.x 后有 Active / Standby 高可用模式          │
└──────────────┬───────────────────────────────────────┘
               │ 告诉 Client 数据在哪个 DataNode
               ▼
┌──────────────────────────────────────────────────────┐
│  DataNode（从节点，N 个）                              │
│  • 真正存数据                                          │
│  • 定时向 NameNode 发送心跳（heartbeat）                  │
│  • 默认每个 Block 128MB，3 副本（分布在不同机器上）        │
└──────────────────────────────────────────────────────┘
```

#### 关键概念记忆

| 概念 | 默认值 | 说明 |
|------|--------|------|
| Block 块大小 | **128 MB** | 一个大文件被切成许多 128MB 的块存储 |
| 副本数 | **3** | 同一块数据存 3 份在不同机器上，1 主 2 备 |
| 文件权限 | 类似 Linux | `rwxr-xr-x`，可通过 `hdfs dfs -chmod` 修改 |
| 默认用户 | 当前登录 Linux 用户 | 考试机房用 `root` 或指定用户 |

### 🛠 3.2 HDFS Shell 命令大全（命令题全覆盖）

> 💡 **命令前缀**：`hadoop fs` 和 `hdfs dfs` **完全等价**，考试写哪个都对。推荐用 `hdfs dfs`（新版本规范）。

#### 【A组】文件 / 目录操作（必背）

```bash
# 列出目录内容（类似 Linux ls）
hdfs dfs -ls /user/library/

# 创建目录（类似 mkdir）
hdfs dfs -mkdir /user/library

# 递归创建目录（类似 mkdir -p）—— 重要！
hdfs dfs -mkdir -p /user/library/books

# 删除文件
hdfs dfs -rm /user/library/books/old.csv

# 递归删除目录（类似 rm -rf）—— 重要！
hdfs dfs -rm -r /user/library/backup/

# 查看文件内容（类似 cat）
hdfs dfs -cat /user/library/books/recording.csv

# 查看文件末尾（类似 tail）
hdfs dfs -tail /user/library/log.txt

# 移动 / 重命名（类似 mv）
hdfs dfs -mv /user/library/a.csv /user/library/b.csv

# 复制（类似 cp）
hdfs dfs -cp /user/library/a.csv /user/backup/

# 查看目录大小
hdfs dfs -du -h /user/library/
```

#### 【B组】本地 ⇄ HDFS 上传下载（必背！命令题最爱）

```bash
# ===== 本地 → HDFS（上传）=====

# put：复制上传，保留本地源文件
hdfs dfs -put /root/books/recording1101.csv /user/library/books/

# copyFromLocal：和 put 完全一样，语义更明确
hdfs dfs -copyFromLocal /root/books/*.csv /user/library/books/

# moveFromLocal：移动上传，删除本地源文件
hdfs dfs -moveFromLocal /root/books/temp.csv /user/library/books/

# ===== HDFS → 本地（下载）=====

# get：复制下载
hdfs dfs -get /user/library/books/recording.csv /root/download/

# copyToLocal：和 get 一样
hdfs dfs -copyToLocal /user/library/books/result.csv /root/

# ===== HDFS 内部复制 =====
hdfs dfs -cp /user/library/a.csv /user/backup/a.csv
```

#### 【C组】权限 / 属性 / 管理命令

```bash
# 修改文件权限（类似 chmod）
hdfs dfs -chmod 755 /user/library/books/

# 修改文件所有者
hdfs dfs -chown root:root /user/library/

# 查看集群状态（DataNode 列表、容量）
hdfs dfsadmin -report

# 进入/退出安全模式（HDFS 启动后默认在安全模式）
hdfs dfsadmin -safemode leave    # 退出安全模式（才能写入）
hdfs dfsadmin -safemode get      # 查看安全模式状态

# 格式化 HDFS（首次安装时用，考试不会考，但要知道）
hdfs namenode -format
```

#### 【D组】高级命令（偶尔考）

```bash
# 设置文件副本数
hdfs dfs -setrep 3 /user/library/books/a.csv

# 查看文件状态详情
hdfs dfs -stat "%n size=%s" /user/library/books/a.csv

# 从本地文件系统追加内容到 HDFS 文件
hdfs dfs -appendToFile local.log /user/library/log.txt
```

## 四、Part 2 · HBase 分布式数据库

### 🧱 4.1 零基础入门：HBase 是什么？

**一句话理解**：HBase 是建立在 HDFS 之上的**列式 NoSQL 数据库**，适合海量数据的**随机读写**（点查），比如查"用户 10086 的最新行为记录"这种查询。

#### 核心概念（跟关系型数据库对比）

| 关系型数据库（MySQL） | HBase | 说明 |
|---------------------|-------|------|
| 数据库（Database） | → | HBase 没有数据库概念 |
| 表（Table） | **表（Table）** | 类比，但结构大不同 |
| 行（Row） | **行键（RowKey）** | HBase 里 RowKey 是唯一主键，按字典序排序 |
| 列（Column） | **列族（ColumnFamily）** | 列族是必须先定义的，HBase 物理按列族存储 |
| — | **列限定符（Qualifier）** | 列族下的具体列名，不需要预先定义！ |
| — | **单元格（Cell）** | 由 RowKey + 列族 + Qualifier + 时间戳 唯一确定 |
| — | **版本（Version）** | 同一个 Cell 可以存多个时间戳的版本，默认取最新 |

#### 用一张图理解 HBase 结构

```
HBase Table: "person"
│
├── 列族 "info"（必须预先定义）
│   ├── Qualifier: "name"   → Cell: "张三" (timestamp=20260101)
│   ├── Qualifier: "age"    → Cell: "25"  (timestamp=20260101)
│   └── Qualifier: "email"  → Cell: "zhangsan@qq.com"
│
└── 列族 "data"（必须预先定义）
    └── Qualifier: "score"  → Cell: "98"

RowKey: "1001"  —— 类似 MySQL 的主键，但支持区间扫描
```

### 🛠 4.2 HBase Shell 命令大全（命令题全覆盖）

> 💡 HBase Shell 是进入 `hbase shell` 之后的交互式命令，**每条命令后不用加分号**（Ruby 语法）。

#### 启动 HBase Shell

```bash
# 在 Linux 终端执行：
hbase shell

# 进入后会看到：
hbase(main):001:0> 
```

#### 【A组】DDL（数据定义语言）— 创建/修改/删除表

```bash
# 查看所有表
hbase(main):001:0> list

# 创建表：create '表名', '列族1', '列族2', ...
# 例：创建 person 表，有 info 和 data 两个列族
hbase(main):002:0> create 'person', 'info', 'data'

# 查看表结构
hbase(main):003:0> describe 'person'

# 修改表（添加列族）—— alter
hbase(main):004:0> alter 'person', 'address'

# 删除列族
hbase(main):005:0> alter 'person', {NAME => 'address', METHOD => 'delete'}

# 清空表（保留表结构，只删数据）
hbase(main):006:0> truncate 'person'

# 禁用表（改结构前必须先 disable）
hbase(main):007:0> disable 'person'

# 启用表
hbase(main):008:0> enable 'person'

# 删除表（必须先 disable！）
hbase(main):009:0> disable 'person'
hbase(main):010:0> drop 'person'

# 判断表是否存在
hbase(main):011:0> exists 'person'
```

#### 【B组】DML（数据操作语言）— 增删改查（必考！）

```bash
# ===== 增（插入/修改数据）—— put =====
# put '表名', 'RowKey', '列族:Qualifier', '值'

# 插入一行数据
hbase(main):012:0> put 'person', '1001', 'info:name', '张三'
hbase(main):013:0> put 'person', '1001', 'info:age', '25'
hbase(main):014:0> put 'person', '1001', 'info:email', 'zhangsan@qq.com'
hbase(main):015:0> put 'person', '1001', 'data:score', '98'

# 再插入一行
hbase(main):016:0> put 'person', '1002', 'info:name', '李四'
hbase(main):017:0> put 'person', '1002', 'info:age', '30'

# ===== 查单行 —— get =====
# get '表名', 'RowKey'
hbase(main):018:0> get 'person', '1001'

# 指定只查某个列族
hbase(main):019:0> get 'person', '1001', 'info'

# 指定查某个 Qualifier
hbase(main):020:0> get 'person', '1001', 'info:name'

# ===== 全表扫描 —— scan =====
# scan '表名'
hbase(main):021:0> scan 'person'

# 指定只扫描某个列族
hbase(main):022:0> scan 'person', 'info'

# 指定 RowKey 范围扫描（非常有用！）
hbase(main):023:0> scan 'person', {STARTROW => '1001', STOPROW => '1003'}

# ===== 删 —— delete =====

# 删除某一个 Cell（某个 Qualifier 的值）
hbase(main):024:0> delete 'person', '1001', 'info:email'

# 删除一整行（所有列族的所有 Qualifier）
hbase(main):025:0> deleteall 'person', '1001'

# ===== 改 —— 直接 put 覆盖 =====
# HBase 没有单独的 update 命令，再次 put 相同的位置就覆盖了旧值
hbase(main):026:0> put 'person', '1001', 'info:age', '26'   # 年龄从25改成26
```

#### 【C组】退出 Shell

```bash
hbase(main):027:0> exit
```

## 五、Part 3 · MapReduce 编程（Python Streaming）

### 🧱 5.1 零基础入门：MapReduce 是什么？

**一句话理解**：MapReduce 是 Hadoop 的**分布式计算模型**——它把一个大计算任务拆成无数小任务，让一群电脑**并行处理**。你只需要写两个函数：`Mapper` 和 `Reducer`，剩下的 Hadoop 帮你搞定。

#### 三阶段流程图（考试问答题必考）

```
输入文件（HDFS上的大数据文件）
    │
    ▼
┌─────────────────────────────┐
│     Map 阶段（Mapper）        │
│  对每一行数据调用一次 map()    │
│  输出：<key, value> 键值对     │
│                               │
│  例：输入一行 CSV              │
│  → 输出 <ISBN, 借阅天数>       │
└──────────┬──────────────────┘
           │
           ▼
┌─────────────────────────────┐
│  Shuffle & Sort 阶段          │
│  （Hadoop 自动做，你写不了）   │
│  • 按 key 排序                │
│  • 相同 key 的 value 合并     │
│                               │
│  例：所有同一本书的借阅天数     │
│  [8, 159, 45, ...]           │
└──────────┬──────────────────┘
           │
           ▼
┌─────────────────────────────┐
│    Reduce 阶段（Reducer）     │
│  对每个 key 调用一次 reduce()  │
│  输入：<key, [所有value]>     │
│  输出：最终结果 <key, 聚合值>  │
│                               │
│  例：<ISBN, 总天数>           │
└──────────┬──────────────────┘
           │
           ▼
输出文件（写回 HDFS）
```

#### Hadoop Streaming 通信协议

用 Python 写 MapReduce 时，Mapper 和 Reducer 通过**标准输入（stdin）**和**标准输出（stdout）**跟 Hadoop 通信：

```
HDFS 文件 ──stdin──► Mapper.py ──stdout──► Shuffle ──stdin──► Reducer.py ──stdout──► HDFS
```

**关键约定（考试必背）**：
1. Mapper 从 `sys.stdin` 逐行读取
2. Mapper 输出用 **制表符 `\t`** 分隔 key 和 value：`print("key\tvalue")`
3. Reducer 从 `sys.stdin` 读取（Hadoop 已经按 key 排好序了）
4. Reducer 也用 `print("key\tvalue")` 输出

### 🧪 5.2 标准编程模板（死背！）

#### 标准 Mapper 模板

```python
import sys

def mapper(line):
    # 1. 去掉首尾空白
    line = line.strip()
    if not line:
        return
    
    # 2. 按分隔符拆分（CSV 用逗号，TSV 用 \t）
    fields = line.split(',')   # 改成你的分隔符
    
    # 3. 提取 key 和 value（fields 从 0 开始计数）
    key = fields[N]           # N = key 所在的列索引
    value = fields[M]         # M = value 所在的列索引
    
    # 4. 过滤无效数据（很重要！）
    if not value:
        return
    
    # 5. 输出 key\tvalue（制表符分隔）
    print("{}\t{}".format(key, value))

def main():
    for line in sys.stdin:
        mapper(line)

if __name__ == "__main__":
    main()
```

#### 标准 Reducer 模板

```python
import sys

def reducer(key, values):
    # values 是同一个 key 的所有 value 组成的列表
    # 在这做聚合运算：sum / count / max / min / avg ...
    
    result = sum(int(v) for v in values)   # 最常见的：求和
    result = len(values)                   # 或者：计数
    result = max(int(v) for v in values)   # 或者：最大值
    result = min(int(v) for v in values)   # 或者：最小值
    nums = [int(v) for v in values]        # 或者：平均值
    result = sum(nums) / len(nums)
    
    print("{}\t{}".format(key, result))

def main():
    # 手动分组（因为 Reducer 收到的是排好序的流）
    kvs = {}
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        k, v = line.split('\t')
        kvs.setdefault(k, []).append(v)
    
    for k, v in kvs.items():
        reducer(k, v)

if __name__ == "__main__":
    main()
```

### 🧱 6.1 零基础入门：Spark 是什么？

**一句话理解**：Spark 是**比 Hadoop MapReduce 快 10~100 倍**的分布式计算框架，因为它把数据**放在内存里算**，而 MapReduce 每一步都要**写磁盘**。

#### RDD vs DataFrame（考试问答题高频）

| 对比项 | RDD（弹性分布式数据集） | DataFrame / Dataset |
|--------|----------------------|-------------------|

| 性能 | 普通 | Catalyst 优化 + Tungsten，**更快** |
| 类型检查 | 运行时检查 | 编译时检查（Dataset） |
| 可读性 | 类似 Scala/Python 集合 | 类似 SQL |
| 开发 | `rdd.map(x => x*2)` | `df.filter("age > 18")` |
| 考试高频 | 中等（考 `map`/`reduce`） | **很高**（考 `groupBy`/`filter`/`show`） |
| 创建方式 | `sc.parallelize([1,2,3])` | `spark.read.csv("file.csv")` |

rdd2 = sc.textFile("/path/to/file.txt")                  # 从文件（每行是一个元素）

rdd.map(lambda x: x * x)                    # 对每个元素做变换
rdd.filter(lambda x: x % 2 == 0)            # 过滤

pair_rdd.groupByKey()                        # 按 key 分组（类似 MR 的 shuffle）
pair_rdd.sortByKey()                         # 按 key 排序
pair_rdd.mapValues(lambda v: v * 2)          # 只改 value，不改 key

# ===== Action（行动，立即执行！）=====
rdd.reduce(lambda a, b: a + b)              # 聚合得到单值（最常用！）
rdd.count()                                  # 计数
rdd.collect()                                # 收集到 Driver（小数据用）
rdd.take(5)                                  # 取前 5 个元素
rdd.saveAsTextFile("/path/to/output")        # 输出到 HDFS

# ===== 经典 WordCount（99% 的书里都有）=====
text_file = sc.textFile("/path/to/file.txt")
counts = (text_file
    .flatMap(lambda line: line.split(" "))    # 每行拆成单词
    .map(lambda word: (word, 1))              # 每个单词映射为 (word, 1)
    .reduceByKey(lambda a, b: a + b))         # 按 key 求和

### 考点 1：HDFS 架构与工作原理

**题目**：简述 HDFS 的架构，以及 NameNode 和 DataNode 各自的功能和协作关系。

```
参考答案：
1. HDFS 采用主从架构（Master-Slave）
2. NameNode（主节点，1 个）：
   • 保存文件系统的目录结构和文件块位置的元数据
   • 负责客户端文件读写请求的响应
   • Hadoop 2.x 后支持 Active/Standby 高可用
3. DataNode（从节点，N 个）：
   • 真正存储数据块（默认 128MB/块）
   • 定时向 NameNode 发送心跳和块报告
   • 执行 NameNode 的读写指令
4. 协作流程：
   • 客户端请求 → NameNode 查元数据 → 返回 DataNode 地址列表
   • 客户端直接与 DataNode 交互进行读写
   • NameNode 不参与数据传输，只做"目录引导"
```

### 考点 2：MapReduce 编程模型

**题目**：说明 MapReduce 的基本编程模型和三阶段流程。

```
参考答案：
1. MapReduce = Map 函数 + Reduce 函数
2. 三阶段：
   • Map 阶段：对每一行调用 map()，输出 <key, value> 键值对
   • Shuffle & Sort（Hadoop 自动）：按 key 排序分组
   • Reduce 阶段：对每个 key 调用 reduce()，聚合得到最终结果
3. 优点：自动分布式、容错、可扩展
4. 缺点：每阶段写磁盘、不适合迭代计算、Shuffle 开销大
```

### 考点 3：Hadoop vs Spark 对比（超高频！）

**题目**：对比 Hadoop MapReduce 和 Spark 在性能、编程模型、适用场景上的区别。

| 对比维度 | Hadoop MapReduce | Spark |
|---------|-----------------|-------|
| **数据存储** | 每阶段写磁盘 | 内存计算，避免磁盘 I/O |
| **执行速度** | 慢（磁盘 I/O 瓶颈） | 快 10~100 倍 |
| **编程模型** | 只能 Map + Reduce | DAG，支持迭代 |
| **适用场景** | 大规模离线批处理 | 迭代计算、机器学习、流处理 |
| **容错** | 高（通过磁盘） | 高（RDD 血缘关系） |
| **开发效率** | 高（函数式） | 更高（DataFrame API + SQL） |

### 考点 4：HBase 与关系型数据库对比

**题目**：HBase 和传统关系型数据库（如 MySQL）有什么区别？HBase 适用于什么场景？

```
参考答案：
区别：
1. MySQL：结构化数据，行存储，支持复杂 SQL 连接事务，适合精确查询
2. HBase：列式存储（按列族存储），NoSQL，只支持 RowKey 索引，适合海量数据随机读写

适用场景：

• 时序数据、用户画像、日志系统等
```

### 考点 5：大数据的 4V 特征

**题目**：简述大数据的 4V 特征并举例。

| 特征 | 英文 | 含义 | 举例 |
|------|------|------|------|
| Volume | 体量大 | 数据规模巨大 | 一个视频网站每天 TB 级用户行为数据 |
| Velocity | 速度快 | 实时产生和处理 | 金融交易需要毫秒级处理 |
| Variety | 种类多 | 结构化/半结构化/非结构化 | 社交媒体有文本、图片、视频 |
| Value | 价值密度低 | 有价值的信息只占一小部分 | 视频监控数据中有用信息很少 |

### 考点 6：MapReduce 常见问题与优化

**题目**：MapReduce 可能遇到哪些问题？如何优化？

| 问题 | 原因 | 优化策略 |
|------|------|---------|
| **数据倾斜** | 某些 key 的数据量远大于其他 | 随机拆分大 key、增加 Reducer、自定义分区 |
| **内存不足** | 单个 key 的 value 列表太大 | Combiner 预聚合、增加 JVM 内存 |
| **磁盘 I/O 瓶颈** | 每阶段都写磁盘 | 开启压缩、用 Combiner 减少 Shuffle |
| **Shuffle 慢** | 网络传输量大 | 减少 Shuffle 量、数据本地化 |

### 考点 7：HDFS 三大组件及其关系

**题目**：Hadoop 生态系统中 HDFS、YARN、MapReduce 各自的功能和协作关系。

```
参考答案：
1. HDFS：分布式文件系统，负责存储数据
2. YARN：资源管理器，负责计算资源的调度
3. MapReduce：计算框架，负责执行业务逻辑
4. 协作流程：
   • YARN 先启动 MR 作业的运行环境
   • MR 的 Mapper 从 HDFS 读取数据
   • MR 的 Reducer 处理完写回 HDFS
   • YARN 监控整个作业的执行
```
